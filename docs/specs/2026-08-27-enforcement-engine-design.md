# q0t-gates — движок принуждения правил

## Зачем

В воркспейсах QB и Cowork заявлено 11 обязательных правил. Принуждаются **два**.

| Правило | Принуждается сейчас |
|---|---|
| `preflight` перед commit при изменении БД | хук `preflight-db.sh` — блокирует |
| write-SQL через dbhub | хук `dbhub-sql-guard.sh` — блокирует |
| `postmortem` после инцидента | промпт |
| `qb-vault` search до ответа | промпт |
| Daily-заметка в будни | SessionStart-хук только сообщает статус |
| Slack/Jira/DB — только через субагента | промпт |
| Telegram — только через `telegram-agent` | промпт |
| `/session-report` в конце сессии | промпт |
| Нет LLM-атрибуции в коммитах | промпт |
| Не стейджить `.env` / ключи | промпт |
| Jira-поиск всегда с `fields` | промпт |

Ровно те два, что принуждаются кодом, не нарушаются. Остальные девять живут в промте, а промпт —
это просьба. Просьбу можно не выполнить, и она не выполняется «периодически».

Вывод, из которого растёт весь движок: **правило, которое должно соблюдаться всегда, обязано быть
кодом, а не текстом.** Промпт остаётся для того, что требует суждения; гейт — для того, что можно
проверить.

Это подсистема **A** из четырёх (A — enforcement, B — ревью-панель и реестр находок,
C — отчётность и эскалация, D — оркестратор). B, C и D в эту спеку не входят, но A спроектирована
так, чтобы её аудит-лог стал источником данных для C.

## Границы

**Входит:** движок правил, каскад наследования, три типа проверок, аудит, правила первой волны
для QB и Cowork, порядок раскатки.

**Не входит:** ревью-агенты, реестр тех.долга, дашборды, автогенерация правил, миграция
существующих `preflight-db.sh` и `dbhub-sql-guard.sh` (отдельный этап, см. «Раскатка»).

## Архитектура

### Одна точка входа

`gate.py` регистрируется **один раз глобально** в `~/.claude/settings.json` на все события:
`PreToolUse`, `PostToolUse`, `Stop`, `SubagentStop`, `UserPromptSubmit`.

Регистрация глобальная, но активность определяется наличием файлов правил — в проекте без правил
хук делает быстрый выход. Это снимает необходимость «подключать движок» к каждому проекту:
подключение = положить файл правила.

### Раскладка репозитория

```
~/Developer/q0t-gates/
├── README.md                  ← зачем движок, схема правила, как добавить, как читать аудит
├── gate.py                    ← диспетчер: единственная точка входа
├── engine/
│   ├── cascade.py             ← сбор правил по дереву директорий
│   ├── sources.py             ← вычисление источников (diff, транскрипт, commit_message, …)
│   ├── types/{pattern,script,judge}.py
│   ├── verdict.py             ← формирование ответа хука
│   └── audit.py               ← запись в JSONL
├── library/                   ← склад готовых правил, НЕ активны сами по себе
│   ├── no-secrets-staged.toml
│   ├── no-llm-attribution.toml
│   └── …
├── checks/                    ← скрипты для type = "script"
├── global/                    ← правила, активные во всех проектах (симлинки в library/)
├── tools/set-icon.swift       ← иконка-щит на директорию репозитория
├── tests/
└── docs/specs/
```

`library/` — склад. `global/` и `<project>/.claude/gates/` — активные наборы. Активация правила =
симлинк из `library/`; своё правило проекта лежит файлом на месте.

### Каскад наследования

Хуки Claude Code **не** каскадируются по дереву директорий: они читаются из
`~/.claude/settings.json` и `<CLAUDE_PROJECT_DIR>/.claude/settings.json`, где `CLAUDE_PROJECT_DIR` —
корень сессии. Вложенные `accountant_web/.claude/` сами по себе не подхватываются. CLAUDE.md
ведёт себя иначе — отсюда ожидание наследования, которого в хуках нет.

Поэтому каскад реализует движок:

```
~/Developer/q0t-gates/global/*.toml                  ← везде, всегда
    ↓
~/Developer/QB/.claude/gates/*.toml                  ← вся работа в QB
    ↓
~/Developer/QB/accountant_web/.claude/gates/*.toml   ← только этот сервис
```

Правила собираются от корня дерева вниз. Правило с тем же `id` ниже перекрывает верхнее:

```toml
# accountant_web/.claude/gates/no-llm-attribution.toml
disabled = true
reason   = "форк вендорского кода, атрибуция в истории легитимна"
```

**Точка отсчёта каскада зависит от события:**

| Событие | Отсчёт от |
|---|---|
| `PreToolUse` / `PostToolUse` с `Edit`/`Write`/`NotebookEdit` | директории редактируемого файла |
| прочие `PreToolUse` / `PostToolUse` | `cwd` события |
| `Stop` / `SubagentStop` / `UserPromptSubmit` | `cwd` события |

Иначе правило `accountant_web` не сработает, когда его файл правится из корня QB.

Подъём останавливается на `$HOME` — выше не идём.

### Схема файла правила

Один файл — одно правило. `id` = имя файла без расширения, внутри файла не дублируется.

| Поле | Обяз. | Значения |
|---|---|---|
| `description` | да | зачем правило существует; попадает в аудит |
| `event` | да | `PreToolUse` `PostToolUse` `Stop` `SubagentStop` `UserPromptSubmit` |
| `type` | да | `pattern` `script` `judge` |
| `severity` | да | `block` `ask` `warn` |
| `message` | да | текст, который увидит агент при срабатывании |
| `[[match]]` | нет | когда правило смотрит; пусто = всегда на этом событии |
| `[check]` | да | условие нарушения |
| `[escape]` | нет | легальный обход с аудит-следом |
| `disabled` | нет | `true` выключает унаследованное правило; требует `reason` |
| `fail_closed` | нет | `true` — при ошибке движка правило блокирует, а не пропускает; в первой волне не используется |

`type` указывается **всегда и явно**. Значений по умолчанию у обязательных полей нет: неявный
дефолт в DSL — это скрытое поведение, которое потом стоит часов отладки.

### Матчинг: `[[match]]` — массив таблиц

**ИЛИ между блоками, И внутри блока.** Один блок не покрывает все способы сделать одно и то же:
коммит бывает через `Bash`, а бывает через MCP.

```toml
[[match]]
tool    = "Bash"
command = '^\s*git\s+commit\b'

[[match]]
tool = ["mcp__gitlab-qb__*", "mcp__github__create_or_update_file"]
```

`tool` принимает строку или список, поддерживает glob — без этого каждый новый MCP-сервер тихо
открывает дыру в каждом правиле. Ключ `tool` особый; все прочие ключи блока — имена источников,
значение — регексп.

### Источники

Источники — вычисляемые абстракции. Правило описывает **что** проверяем, а не **как** достаём;
иначе каждое правило пришлось бы дублировать под каждый способ вызова.

| Источник | Что отдаёт |
|---|---|
| `command` | `tool_input.command` (для Bash) |
| `tool_input` | весь JSON инструмента как текст |
| `staged_diff` | `git diff --staged` в `cwd` |
| `commit_message` | сообщение коммита — из `git commit -m` **или** из аргументов MCP |
| `transcript` | текст сессии (только `isSidechain=false`, т.е. основной контекст) |
| `transcript.all` | текст сессии включая субагентов |
| `transcript.tools` | список имён вызванных инструментов и скиллов, основной контекст |
| `prompt` | текст промпта (для `UserPromptSubmit`) |
| `in_subagent` | `"true"` / `"false"` — вызов идёт из субагента |
| `file:<path>` | содержимое файла относительно `cwd` |

`in_subagent` определяется по полю `isSidechain` последней записи транскрипта — наличие поля
подтверждено на реальных транскриптах. Точная надёжность на момент `PreToolUse` проверяется
спайком на этапе 0 (см. «Раскатка»); правила, зависящие от него, до подтверждения не заезжают.

Источники вычисляются **лениво**: `staged_diff` не запускается, если ни одно правило его не
просит.

### Тип `pattern`

Регексп по источнику. Два оператора, взаимоисключающих:

- `deny_if` — нарушение, если регексп **нашёлся**
- `require` — нарушение, если регексп **не нашёлся**

```toml
description = "В QB запрещена LLM-атрибуция в коммитах"
event    = "PreToolUse"
type     = "pattern"
severity = "block"
message  = "Убери Co-Authored-By/Generated with из сообщения коммита — см. rules/python-services.md"

[[match]]
tool    = "Bash"
command = '^\s*git\s+commit\b'

[[match]]
tool = "mcp__gitlab-qb__*"

[check]
source  = "commit_message"
deny_if = 'Co-Authored-By:\s*Claude|Generated with \[?Claude'
```

### Тип `script`

Когда регексп не выражает — например, нужен порядок событий, а не факт их наличия.

```toml
description = "Ответ по тикету BSGD/DESK без предварительного поиска в vault"
event    = "Stop"
type     = "script"
severity = "warn"
message  = "Ты отвечал по тикету, не заглянув в vault. Skill qb-vault обязателен ДО ответа."

[[match]]
transcript = '\b(BSGD|DESK)-\d+\b'

[check]
script = "checks/vault_searched_first.py"
```

Скрипт получает на stdin JSON: исходное событие хука плюс вычисленные источники. Печатает
`{"violated": bool, "reason": "<одна строка>"}`. Ненулевой код возврата или неразбираемый вывод →
правило считается **не** сработавшим, в аудит пишется `error`.

### Тип `judge`

Когда важен не факт, а качество.

```toml
description = "Постмортем написан формально: нет причины до строки кода или опровергнутых гипотез"
event    = "Stop"
type     = "judge"
severity = "ask"
message  = "Постмортем неполон — дозаполни перед закрытием сессии."

[[match]]
"transcript.tools" = 'Skill\(postmortem\)'

[check]
model   = "haiku"
input   = ["transcript"]
timeout = 30
prompt  = """
Ниже транскрипт сессии, в которой писался постмортем.
Проверь ДВА пункта: (1) причина доведена до конкретной строки кода или SQL-предиката,
не остановилась на «сервис вернул ошибку»; (2) зафиксирована хотя бы одна рассмотренная
и опровергнутая гипотеза.
Ответь JSON: {"violated": bool, "reason": "<чего не хватает, одна строка>"}
"""

[escape]
source = "prompt"
marker = "[skip-postmortem-check]"
```

Судья вызывается как `claude -p` с указанной моделью. Вердикт обязан быть JSON фиксированной формы
`{violated, reason}` — движок его валидирует, а не доверяет свободному тексту. Таймаут, непарсимый
ответ, ненулевой код → правило **не** сработало, в аудит `judge_failed`. Судья не должен уметь
заблокировать работу собственной поломкой.

### `severity`

| | `PreToolUse` / `PostToolUse` | `Stop` / `SubagentStop` |
|---|---|---|
| `block` | `permissionDecision: deny`, действие не происходит | сессия не закрывается, агент обязан доделать |
| `ask` | `permissionDecision: ask`, решает человек | то же — решает человек |
| `warn` | действие идёт, `message` уезжает агенту в контекст | сессия закрывается, `message` в контекст |

Новое правило заезжает в `warn`, живёт неделю, потом по аудиту решается судьба. Иначе первый кривой
регексп заставит выключить весь движок.

### `escape` — разовый легальный обход

Правило сработало, но маркер найден → действие пропускается, в аудит уходит `escaped`.

```toml
[escape]
source = "commit_message"
marker = "[allow-env]"
```

Смысл двойной: система без выхода отключается целиком при первом ложном срабатывании; обходы в
логе — данные («гейт обходили 9 раз, всегда на `*.template`» означает, что чинить надо регексп).

**Ограничение по источникам маркера.** `marker` ищется только там, где пишет человек:

| Источник | Допустим | Почему |
|---|---|---|
| `prompt` | да | модель не пишет сообщения пользователя — подделка невозможна |
| `commit_message` | да, с пометкой | навсегда остаётся в истории git, видно на ревью |
| любой другой | **нет** | агент выпишет себе амнистию сам, и движок станет декорацией |

Для `commit_message` движок различает, кто вписал маркер: если в транскрипте нет пользовательского
сообщения, санкционирующего обход, запись идёт как `escaped_by_agent` и попадает в сводку отдельной
строкой. Нынешний `[skip-preflight]` этим уязвим — его может вписать модель, и следа не остаётся.

### Аудит

`~/Developer/q0t-gates/audit/YYYY-MM.jsonl`, одна строка на срабатывание:

```json
{"ts":"2026-08-27T14:31:02Z","rule":"no-secrets-staged","event":"PreToolUse",
 "verdict":"escaped","severity":"block","project":"/Users/q0tik/Developer/QB",
 "cwd":"/Users/q0tik/Developer/QB/accountant_web","session":"055220d1",
 "reason":"config/local.env.template","escape_source":"commit_message"}
```

`verdict`: `violated` `escaped` `escaped_by_agent` `judge_failed` `error`.

`passed` **не пишется**: иначе лог зарастёт записью о каждом вызове инструмента. В аудите живут
только ненормальные исходы, и метрика «гейт мешает» считается по `violated + escaped`.

Аудит — не отладочный лог, а источник данных для подсистемы C: «какие гейты работают, какие только
мешают» — это метрика, а не ощущение.

### Отказоустойчивость

**Fail-open.** Любое необработанное исключение в `gate.py` → `exit 0` (действие разрешено) + запись
`error` в аудит. Гейт, который ломает работу при собственном баге, будет отключён целиком в первый
же день, и защиты не останется вовсе.

Исключение из fail-open: правила с `fail_closed = true` в файле. В первой волне таких нет.

### Производительность

`gate.py` запускается на каждый `PreToolUse`. Бюджет — **не более 50 мс** на быстром пути
(нет применимых правил).

Меры:
- скомпилированный индекс `event → правила` кэшируется в `~/.cache/q0t-gates/index.json`,
  инвалидация по `mtime` директорий правил;
- ленивое вычисление источников;
- быстрый выход до импорта тяжёлых модулей, если индекс для события пуст.

Замер — задача этапа 0. Если бюджет не держится, следующий шаг — сузить matcher в
`settings.json` до конкретных инструментов, генерируя его из набора правил.

## Правила первой волны

### `global/` — все проекты

| id | event | type | severity | Что проверяет |
|---|---|---|---|---|
| `no-secrets-staged` | PreToolUse | pattern | warn → block | в staged нет `.env`, `*.key`, `*.pem`, `id_rsa` |
| `session-report-on-stop` | Stop | script | warn | была реальная работа (Edit/Write/commit), а `/session-report` не вызван |

### `QB/.claude/gates/`

| id | event | type | severity | Что проверяет |
|---|---|---|---|---|
| `no-llm-attribution` | PreToolUse | pattern | block | нет `Co-Authored-By: Claude` в сообщении коммита |
| `jira-search-fields` | PreToolUse | pattern | block | `jira_search_issues` вызывается с непустым `fields` |
| `postmortem-required` | Stop | script | warn → block | обсуждался инцидент → скилл `postmortem` вызван |
| `postmortem-quality` | Stop | judge | ask | постмортем доведён до причины и содержит опровергнутую гипотезу |
| `vault-searched-first` | Stop | script | warn | по тикету/человеку был поиск в vault **до** первого ответа |
| `daily-note-weekday` | Stop | script | warn | в будний день с реальной работой daily-заметка тронута |
| `heavy-reads-via-subagent` | PreToolUse | pattern | warn | читающие Slack/Jira/dbhub-вызовы идут не из основного контекста |

### `Cowork/.claude/gates/`

| id | event | type | severity | Что проверяет |
|---|---|---|---|---|
| `telegram-via-agent` | PreToolUse | pattern | block | `mcp__telegram__*` не вызывается из основного контекста |

`heavy-reads-via-subagent` и `telegram-via-agent` зависят от источника `in_subagent` и заезжают
только после подтверждения спайком на этапе 0.

## Тестирование

`pytest`, зависимостей нет — `tomllib` в стандартной библиотеке Python 3.14.

- **Юнит:** каскад (перекрытие по id, `disabled`, остановка на `$HOME`), матчинг (ИЛИ/И, glob по
  `tool`), каждый источник, валидация схемы правила.
- **Golden-тесты правил:** на каждое правило — фикстура события JSON и ожидаемый вердикт, минимум
  один срабатывающий и один не срабатывающий случай. **Правило без теста не заезжает в `global/`
  или `.claude/gates/`** — иначе набор правил станет неревьюируемым за месяц.
- **Судья:** мокается; тестируется обработка таймаута, мусорного вывода и валидного вердикта, а не
  качество суждения.
- **Fail-open:** тест на то, что исключение в любом типе проверки даёт `exit 0` и запись `error`.

## Раскатка

**Этап 0 — спайк (до кода движка).**
Проверить два факта, от которых зависит часть правил:
1. надёжно ли `isSidechain` разделяет основной контекст и субагента **на момент `PreToolUse`**;
2. накладные расходы пустого Python-хука на каждый `PreToolUse` — держится ли бюджет 50 мс.

Результат — запись в этой спеке. Правила, зависящие от (1), при отрицательном исходе выбывают из
первой волны.

**Этап 1 — движок и pattern-правила.**
`gate.py`, каскад, источники, `type = "pattern"`, аудит, README, иконка. Заезжают `no-secrets-staged`,
`no-llm-attribution`, `jira-search-fields` — все в `warn`.

**Этап 2 — наблюдение, неделя.**
Ничего не блокируется. Читается аудит: сколько срабатываний, сколько ложных.

**Этап 3 — ужесточение и остальные типы.**
Правила без ложных срабатываний переводятся в `block`. Добавляются `script` и `judge`:
`postmortem-required`, `postmortem-quality`, `vault-searched-first`, `daily-note-weekday`,
`session-report-on-stop`.

**Этап 4 — миграция существующих хуков.**
`preflight-db.sh` и `dbhub-sql-guard.sh` переписываются как правила движка. Отдельно и последними:
это единственные два работающих гейта, ломать их ради единообразия нельзя. Выигрыш — они попадут
в аудит, и `[skip-preflight]` получит защиту от самоамнистии агента.

## Риски

| Риск | Митигация |
|---|---|
| Ложные срабатывания → движок выключают целиком | `warn`-first, `escape`, `disabled` на уровне поддиректории |
| Оверхед на каждом вызове инструмента | кэш индекса, ленивые источники, бюджет 50 мс, замер на этапе 0 |
| Баг в движке блокирует работу | fail-open + запись `error` |
| Судья тормозит или врёт | таймаут, `judge_failed` = не сработало, только на `Stop`, не на `PreToolUse` |
| Модель учится ставить галочки формально | `judge` на критичных правилах; аудит показывает подозрительные паттерны |
| Набор правил разрастается и становится неревьюируемым | правило без golden-теста не заезжает; `description` обязателен |
